# Thread 名称治理

## 范围门禁（先判断）

仅用户直接持有的主 Thread 由主 agent 使用本 skill。

如果系统或协作上下文将当前身份标识为 non-root/spawned agent、subagent（子代理）、
worker、reviewer 或其他内部 agent：立即跳过。
不要读取本 skill 的其余内容，不要查找标题工具，不要尝试改名或回读标题，也不要
向主 agent 回报标题治理、标题工具不可用或改名失败。父级主 Thread 的标题治理只由主 agent 负责；继续执行获派的实际子任务。

## 核心原则

将 Thread 标题作为可扫描的生命周期索引。默认格式为：

```text
「状态」工作项/类型｜主题
```

先读取当前工作目录适用的 `AGENTS.md` 和项目专用命名 skill。项目级规则可以显式覆盖本 skill 的对应部分；
未明确覆盖的部分继续继承下面的全局默认值。

## 自动检查点

通过范围门禁后，无论用户是否提及 Thread 命名，都按以下检查点判断当前主 Thread：

1. 新主 Thread 的首个 assistant turn：在开展主要工作前规范化标题。
2. 已有主 Thread 恢复推进或收到新的实质任务：检查状态和工作中心。
3. 生命周期发生真实变化：立即同步状态。
4. 发现更权威工作项或当前标题已经失真：更新工作项或主题。
5. 每次结束回复前：轻量判断本轮是否触发以上变化；未触发时不重复加载完整流程或改名。

每次需要治理时按以下顺序执行：

1. 默认只处理当前 Thread；批量操作必须有明确授权和项目边界。
2. 读取当前工作目录适用的 `AGENTS.md` 和项目专用命名 skill。
3. 根据 Thread 的实际工作中心和生命周期选择状态、工作项或类型、主题。
4. 将候选标题与现有标题比较；只有实质差异才执行更新。
5. 使用可用的 Thread 标题工具写入。
6. 重新读取或列出当前 Thread；只有回读一致才算更新成功。

## 状态

| 状态 | 判定条件 |
|---|---|
| `进行中` | 正在分析、实现、验证或等待本轮工作继续 |
| `已完成` | Thread 范围内的交付物与必要验证已经完成 |
| `已归档` | 主要作为调研、背景或历史参考保留，不再主动推进 |
| `已挂起` | 内容仍有效，但明确等待依赖、决策或外部条件 |
| `已废弃` | 已被替代、否决或不再作为当前依据，保留用于追溯 |

UI 的 `idle`、长时间无活动或当前没有运行中的 turn 都不等于 `已挂起`。
`已完成` 只描述 Thread 生命周期，不自动表示代码已合入、方案已批准、架构已冻结
或版本已发布。评审 Thread 完成也不表示被评审对象已经通过。

## 工作项或类型

按以下优先级选择：

1. 存在权威工作项、议题或决策编号时直接使用，例如 `DEMO-12`、`DEMO-34`、`DEMO-56`、
   `ADR-001`。
2. 对编号工作项进行独立评审时允许 `编号/评审复核`。
3. 没有稳定编号时，从全局通用类型中选择一个：

```text
项目治理  问题诊断  功能开发  缺陷修复
代码重构  架构设计  契约规范  测试验证
评审复核  技术调研  实施规划  文档编制
发布交付  环境运维  数据分析  背景输入
```

不要组合两个通用类型。不要把项目名、分支名、agent 名、日期或 Thread ID 放入
该字段。

## 主题

- 描述最终工作的中心，而不是机械复述第一条 prompt。
- 保持简洁，通常为 8–24 个字符；允许稳定的英文产品名和技术术语。
- 不重复状态、工作项、类型或“任务”等无信息词。
- 工作中心发生实质变化时更新主题；仅有实现细节变化时保持标题稳定。

## 必须更新标题

出现以下任一情形时更新当前标题：

- 新 Thread 尚未采用规范格式；
- 生命周期在 `进行中`、`已完成`、`已归档`、`已挂起`、`已废弃` 之间真实变化；
- 发现了更权威的工作项、议题或决策编号；
- 主要问题、主要交付物或工作中心发生实质变化；
- 旧标题只反映最初请求，已不能覆盖当前主要工作；
- 标题存在错误、歧义、过时范围或格式违规。

## 稳定性与防抖

以下情况本身不触发改名：

- 同一任务内的实现细节、验证步骤或背景补充；
- 不改变主要交付物的普通追问；
- 仅能让措辞稍微更顺畅的修改；
- UI `idle`、暂时无运行中 turn 或正常等待普通对话回复；
- 单个 assistant turn 结束，但 Thread 的整体范围尚未完成。

`已挂起` 只用于明确暂停并等待依赖、决策或外部条件。普通多轮确认、逐题讨论或等待
用户下一条回复不自动视为 `已挂起`。恢复已挂起的工作时改为 `进行中`；已完成 Thread
收到新的实质任务时，也应先恢复为 `进行中`。

## 项目级覆盖

- 项目级规则明确规定的格式、状态、类型、编号或触发条件优先。
- 项目级规则未明确覆盖的部分继续继承本全局规则。
- 仅存在项目级 `AGENTS.md` 不表示全部全局规则失效。
- 项目要求完整替代全局策略时，必须明确写出完整覆盖范围，并重新声明首轮触发、
  生命周期边界、授权范围和验证要求。

## 执行与验证

- 需要更新时直接使用当前可用的 Thread 标题工具，无需等待用户另行授权。
- 标题已准确时不得为了措辞优化而重复写入。
- 子代理不得执行本节；主 agent 不得要求子代理代为治理父级主 Thread 标题。
- 工具不可用或更新失败时继续完成用户主要任务，并在最终回复中说明实际结果，
  不得声称已经完成改名。
- 标题中的 `已归档` 只是生命周期语义；修改 Codex App archive 属性需要独立授权。

## 示例

以虚构的导出功能为例，一次独立复核从开始、等待接口样例到完成：

```text
「进行中」DEMO-34/评审复核｜导出结果复核
「已挂起」DEMO-34/评审复核｜等待接口样例
「已完成」DEMO-34/评审复核｜导出结果复核
```

其他合法示例：

```text
「进行中」项目治理｜全局 Thread 命名规范
「已完成」DEMO-56｜导出格式验证
「已归档」技术调研｜表格导出方案对比
「已废弃」架构设计｜旧导出方案
```

## 常见错误

- 子代理把自己的内部会话当作新主 Thread，读取本 skill 并寻找标题工具。
- 将 `idle` 映射为 `已挂起`。
- 因 Thread 完成而宣称评审对象已批准、代码已合入或架构已冻结。
- 未读上下文就按关键词批量改名。
- 用 `架构设计/评审复核` 组合两个通用类型。
- 状态变化后仍保留旧标题。
- 将标题 `已归档` 等同于修改 App 的 archive 属性；后者需要单独授权。
